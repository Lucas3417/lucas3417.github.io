## 为什么会有这个博客

这个博客的初衷很简单：**记录我的法律学习与 AI 探索**。

**关于法律学习。** 我是一名法学院学生，主要兴趣在民商法领域，特别是：

- 民法典表见代理制度——一个在"被代理人的可归责性"上争论不休的议题
- 建设工程法律实务——从合同效力、竣工验收到造价鉴定、农民工工资保障
- 比较法研究——德国民法典（BGB）与中国民法典的对照阅读

法律学习最怕"看过就忘"。条文会改、解释会更新、案例会堆积，如果不及时整理成文，知识永远是碎片化的。写博客就是逼迫自己把输入转化为输出：能写清楚，才算真正想明白。

**关于 AI 探索。** 我同时也在探索 AI 如何改变法律学习的方式。最直接的产品是本站的 [BGB 法典查询工具](/bgb/)——它内置了德国民法典全部 2520 条条文的中文译文，支持离线查询原文与中文，并结合大模型做 AI 联想检索。这是我自己用 AI 辅助搭建的第一个小工具，也是"学习 + 编程 + 法律"三者结合的一次尝试。

## 搭建方法

这个博客采用**静态站点**方案，全部免费、无需备案：

| 环节 | 方案 | 费用 |
|---|---|---|
| 站点生成 | Hugo（Go 编写的静态站点生成器） | 免费 |
| 写作方式 | Markdown 本地写作 | 免费 |
| 源码托管 | GitHub 私有仓库 | 免费 |
| 网站托管 | GitHub Pages | 免费 |
| 部署方式 | GitHub Actions 自动构建，push 即上线 | 免费 |
| AI 代理 | Cloudflare Workers（隐藏 API Key、解决跨域） | 免费额度内 |

**为什么选静态站点？** 动态博客（WordPress 等）需要服务器和数据库，而个人博客的核心需求只是"写文章、给人看"。静态站点在构建时直接生成纯 HTML，加载快、安全性高、几乎零维护成本。Hugo 的构建速度极快（本站全站构建不到 1 秒），配合 Markdown 写作，体验很舒服。

**发布流程。** 我在本地用 Markdown 写文章，然后一键推送到 GitHub，GitHub Actions 自动执行 Hugo 构建并部署到 GitHub Pages。从写完到上线大约 1 分钟，整个过程不需要登录任何后台。

**关于 AI 功能的架构。** BGB 工具的 AI 联想走 Cloudflare Workers 代理：请求先到 Worker，由 Worker 转发给大模型 API 并注入密钥，浏览器端不接触任何 Key，同时通过 CORS 头解决了跨域限制。这样既保证了安全，又让工具可以在任何浏览器（包括手机）里使用。
